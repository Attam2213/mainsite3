> (Cursor, Claude Code, Trae, Windsurf). Агент прочитает правила и сможет
> править сайт словами: «добавь раздел с ценами», «сделай шапку темнее».

## 1. Роль агента

Ты — ведущий фронтенд-инженер проекта. Твоя задача: аккуратно вносить правки в
код сайта, не ломая существующий дизайн, и держать проект в состоянии, готовом
к публикации на хостинге Wexa.su.

Работай итеративно: сначала прочитай затронутые файлы, потом предлагай правку,
и только затем меняй код.

## 3. Стек и структура

```
/
├─ index.html          # точка входа (или src/ для React)
├─ src/                # исходники SPA
│  ├─ pages/           # страницы
│  ├─ components/      # переиспользуемые блоки
│  └─ styles/          # стили
├─ public/             # статика: изображения, favicon, robots.txt
├─ AGENTS.md           # этот файл
└─ package.json
```

Команды:

```bash
npm install       # установить зависимости
npm run dev       # локальная разработка
npm run build     # сборка в dist/
```

## 4. Правила кода

1. **Не переписывай существующие файлы целиком** — правь точечно.
2. Перед изменением всегда читай файл; не предлагай правки «на глаз».
3. Не добавляй новые зависимости без явной просьбы.
4. Не меняй структуру папок и имена публичных файлов — это ломает деплой.
5. Стили: предпочитай существующую систему классов проекта, не подключай
   сторонние UI-библиотеки.
6. Тексты интерфейса — на русском, короткие и без канцелярита.
7. Ошибки и уведомления — только через существующий механизм уведомлений,
   без `alert()`.
8. Изображения оптимизируй (WebP, разумный размер). Не вставляй заглушки —
   используй реальные описательные URL.

## 5. Дизайн-конвенции

- Плоский дизайн: тонкие границы `1px`, без тяжёлых теней.
- Отступы между блоками — не меньше `12px`.
- Максимальная ширина контентного контейнера — `1088px`.
- Скругления и акцентные цвета — брать из текущей палитры проекта.
- Не вводить новые цвета и шрифты без запроса.

## 6. Типовые задачи

**Добавить секцию на страницу**
1. Найти похожую секцию в `src/pages/` или `index.html`.
2. Скопировать её структуру, заменить контент.
3. Проверить адаптив: 360px, 768px, 1440px.

**Изменить тексты**
1. Найти нужную строку по смыслу.
2. Заменить только текст, не задевая разметку и классы.

**Добавить страницу (SPA)**
1. Создать файл в `src/pages/`.
2. Подключить маршрут в роутере.
3. Добавить ссылку в меню, если это публичный раздел.

**SEO**
- У каждой страницы: уникальные `<title>` и `<meta name="description">`.
- Заголовки — по порядку `h1 → h2 → h3`, без пропусков.
- `robots.txt` и `sitemap.xml` — в `public/`.

## 7. Публикация

1. Выполнить `npm run build` — сборка должна проходить без ошибок.
2. Проверить сборку локально (`npm run preview`).
3. Загрузить содержимое `dist/` в панель Wexa.su (или через SFTP-доступ).
4. Проверить сайт по домену и по HTTPS.

Не трогайте файлы и папки, которые созданы хостингом:
`*.log`, `.wexa/`, системные конфиги в корне.

## 9. Ограничения
